# Cicerone Platform Audit & Improvement Plan — v0

> **Date:** 2026-04-07
> **Branch:** `claude/add-audit-plans-wuR1I`
> **Scope:** Initial baseline audit of the Cicerone AI travel itinerary platform and a prioritized checklist of improvements.

This document is the **first iteration** (`v0`) of the platform audit. It captures the current state of the codebase, identifies risks, and tracks the work required to harden, clean up, and grow the platform. Subsequent iterations should land as `v1.md`, `v2.md`, etc., as work gets done and new findings emerge.

---

## 1. Executive Summary

Cicerone is a React 18 + Vite + TypeScript single-page app that uses **Google Gemini** for itinerary generation and **Supabase** for auth and persistence. The product surface is feature-rich (multi-step travel form, AI itinerary generation, refinement, interactive map, AI chat, wishlist parsing, cloud sync, dark mode) but the codebase has several critical issues:

- **Duplicate, divergent code trees** at the repo root and under `frontend/` — only `frontend/` is wired up via `index.tsx`.
- **Gemini API key is bundled into the client** via `vite.config.ts` `define`, exposing it to anyone inspecting the bundle.
- **No tests, linting, formatting, CI, or pre-commit hooks** — zero developer tooling beyond `vite`.
- **Wildcard dependency pin** on `@google/genai` (`"*"`) in `package.json`.
- **Oversized components** (e.g. `frontend/components/ItineraryView.tsx` ~941 lines) and weak error handling (`alert()` everywhere).

The fundamentals are solid (modern React, real AI integration, real auth) but the platform needs a cleanup pass before adding more features.

## 3. Findings by Category

### 3.1 Security 🔴

- **CRITICAL — Gemini API key exposed to the client.** `vite.config.ts` injects `process.env.API_KEY` into the bundle via `define`, and `frontend/services/geminiService.ts` reads it directly. Anyone can extract the key from the JS bundle or DevTools network tab.
- **No backend proxy.** `backend/api.ts` exists but is a stub and is not imported anywhere. There is no server-side surface to keep secrets or rate-limit requests.
- **Supabase RLS unverified.** The frontend uses the `anon` key (correct), but there is no in-repo confirmation that the `travels` table has Row-Level Security enabled. Without RLS, any user could read/write any row.
- **No input validation / sanitization** before sending user-supplied form fields, chat messages, and wishlist URLs to Gemini.
- **No rate limiting** on AI calls, so a malicious client (with the leaked key) can drain the Gemini quota.

### 3.2 Code Quality 🟠

- **Massive components.** `frontend/components/ItineraryView.tsx` is ~941 lines and mixes rendering, state, refinement orchestration, weather, and settings. `TravelForm.tsx` is ~371 lines.
- **Generic error handling.** Most failures surface as `alert("Failed to ...")`. No error boundaries, no inline error states, no retries.
- **Magic strings.** Gemini model names (`"gemini-2.5-flash"`, `"gemini-3-pro-preview"`), interest options, transport types, and activity types are sprinkled throughout components instead of being centralized.
- **TypeScript not strict.** `tsconfig.json` does not enable `"strict": true`, uses `allowJs` and `skipLibCheck`. Real type safety is partial.
- **Inconsistent state management.** Mix of `useState`, localStorage, and Supabase calls scattered across components — no global store or React Context for shared state.

### 3.3 Dependencies 🟠

- `@google/genai`: pinned to `"*"` — any breaking release will silently break production.
- No `eslint`, `prettier`, `vitest`, `husky`, `lint-staged`, or `@types/node`.
- `react-leaflet` + `leaflet` are imported but the map surface is minimal — possible bundle bloat for limited value.

### 3.4 Missing Infrastructure 🔴

- **No tests.** Zero `*.test.ts(x)` or `*.spec.ts(x)` files.
- **No linting / formatting.** No `.eslintrc*`, no `.prettierrc*`.
- **No CI.** No `.github/workflows/`.
- **No pre-commit hooks.** No husky, no `pre-commit-config.yaml`.
- **No `.env.example`.** New contributors have no idea which env vars are required (`API_KEY`, `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, etc.).
- **No error tracking.** No Sentry or equivalent.
- **README is one paragraph** ("Run and deploy your AI Studio app") and gives no architecture / contribution context.

### 3.5 Tech Debt / Dead Code 🟠

- Entire root-level `components/`, `services/`, `App.tsx`, `types.ts`, and `backend/api.ts` are unused.
- Unused root-level components: `ArtistCard.tsx`, `CustomCursor.tsx`, `FluidBackground.tsx`, `GlitchText.tsx`.
- Buttons referencing features that aren't wired up (e.g. "Download / Export" in `ItineraryView`).
- Wishlist analyzer falls back to hardcoded defaults silently on parse failure.

### 3.6 UX & Performance 🟡

- No skeleton loaders — only spinners.
- No accessibility pass: very few `aria-*` attributes, lots of `<div>` soup, no documented keyboard navigation.
- No bundle analysis; Leaflet is eagerly loaded even on routes that don't need a map.
- No offline / PWA / service worker.
- Dark mode toggle exists but persistence story unclear.

### 3.7 Strengths ✅

- Modern hooks-based React with immutable state updates.
- Real AI integration with structured prompt → typed `Itinerary` flow.
- Real auth + cloud persistence via Supabase.
- Thoughtful UX touches: animated landing, multi-step form, activity locking, refinement.
- Shared `shared/types.ts` keeps the data model consistent across services and components.

## 4. Prioritized TODO Checklist

Tick boxes as work lands. When this list is mostly green, snapshot it and start `plans/v1.md` with the next round.

### 🔴 Critical — must fix before adding new features

- [ ] **Move Gemini API key to a server-side proxy.** Stand up a real backend route (Vercel serverless, Supabase Edge Function, or similar) that calls Gemini with the secret key, and have the frontend hit that route instead of `@google/genai` directly. Remove `API_KEY` from `vite.config.ts` `define`.
- [ ] **Delete dead code** at the repo root: `App.tsx`, `types.ts`, `components/`, `services/`, `backend/api.ts`, and any unused components (`ArtistCard`, `CustomCursor`, `FluidBackground`, `GlitchText`). Verify nothing still imports them first.
- [ ] **Verify Supabase RLS** is enabled on the `travels` table (and any other user-owned tables) and document the policies in the repo (e.g. `supabase/policies.sql`).
- [ ] **Pin `@google/genai`** to a specific minor version in `package.json` and run `npm install` to lock it.
- [ ] **Add `.env.example`** documenting `API_KEY`, `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, and any other required variables.
- [ ] **Validate / sanitize user input** before sending to Gemini (length caps, URL allow-list for wishlist parser, strip control chars).

### 🟠 High — strongly recommended

- [ ] **Add ESLint + Prettier** with a sensible React/TypeScript preset and a `npm run lint` / `npm run format` script.
- [ ] **Enable TypeScript strict mode** (`"strict": true`, `"noUncheckedIndexedAccess": true`) and fix the resulting errors incrementally.
- [ ] **Add a `npm run typecheck`** script (`tsc --noEmit`) and wire it into CI.
- [ ] **Set up GitHub Actions CI** to run lint, typecheck, and build on every PR.
- [ ] **Add Husky + lint-staged** so commits cannot land with lint errors or accidentally committed `.env` files.
- [ ] **Introduce error boundaries** at the app shell and around the itinerary view, showing user-friendly fallback UI.
- [ ] **Replace `alert()` calls** with inline toast / banner error UI.
- [ ] **Split `ItineraryView.tsx`** into smaller subcomponents (DayList, ActivityCard, SettingsPanel, WeatherStrip, RefinementBar).
- [ ] **Centralize constants** (Gemini model IDs, interest options, transport types, activity types) in `frontend/constants.ts` or `shared/constants.ts`.

### 🟡 Medium — should do

- [ ] **Add a test runner** (Vitest + React Testing Library) and write smoke tests for: itinerary parsing, refinement merge logic, Supabase save/load, and the travel form reducer.
- [ ] **Add error tracking** (Sentry or equivalent) for production.
- [ ] **Add structured logging** in services (`geminiService`, `weatherService`, Supabase wrapper) instead of ad-hoc `console.error`.
- [ ] **Lazy-load the map** so Leaflet is only fetched when the user views an itinerary with a map.
- [ ] **Bundle analysis** (`vite-plugin-visualizer`) and a documented size budget.
- [ ] **Accessibility pass**: semantic landmarks, `aria-*` for interactive controls, keyboard nav for the itinerary list, color-contrast check.
- [ ] **Persist dark mode** preference (localStorage or Supabase user metadata).
- [ ] **Document the data model** (`shared/types.ts`) and the Supabase schema in `plans/` or `docs/`.
- [ ] **Rewrite the README** with: what Cicerone is, architecture diagram, env vars, local dev, deploy.

### 🟢 Low — nice to have

- [ ] **Implement export** (PDF / iCal / shareable link) for the existing "Download" button.
- [ ] **Add SWR or React Query** for Supabase reads with caching + revalidation.
- [ ] **Complete the weather service** integration (currently a thin stub).
- [ ] **Offline / PWA support** with a service worker and an offline indicator.
- [ ] **Real-time collab** on shared itineraries via Supabase Realtime.
- [ ] **Email confirmation / reminders** for upcoming trips.
- [ ] **i18n scaffolding** so the UI is not English-only.
