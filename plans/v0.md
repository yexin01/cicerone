# Cicerone Platform Audit & Improvement Plan — v0

> **Date:** 2026-04-07
> **Branch:** `claude/add-audit-plans-wuR1I`
> **Scope:** Initial baseline audit of the Cicerone AI travel itinerary platform, a product vision for "the only app a traveler needs", and a prioritized checklist of engineering + product improvements.

This document is the **first iteration** (`v0`) of the platform audit. It captures the current state of the codebase, identifies risks, lays out the product vision for where Cicerone should go, and tracks the work required to harden, clean up, and grow the platform. Subsequent iterations should land as `v1.md`, `v2.md`, etc., as work gets done and new findings emerge.

**How to read this doc:** Sections 1–3 are the engineering audit. Sections 4–5 are the product vision and feature roadmap. Section 6 is the unified checklist. Sections 7–9 are open questions, sequencing, and next steps.

---

## 1. Executive Summary

Cicerone is a React 18 + Vite + TypeScript single-page app that uses **Google Gemini** for itinerary generation and **Supabase** for auth and persistence. The product surface is feature-rich (multi-step travel form, AI itinerary generation, refinement, interactive map, AI chat, wishlist parsing, cloud sync, dark mode) but the codebase has several critical issues:

- **Duplicate, divergent code trees** at the repo root and under `frontend/` — only `frontend/` is wired up via `index.tsx`.
- **Gemini API key is bundled into the client** via `vite.config.ts` `define`, exposing it to anyone inspecting the bundle.
- **No tests, linting, formatting, CI, or pre-commit hooks** — zero developer tooling beyond `vite`.
- **Wildcard dependency pin** on `@google/genai` (`"*"`) in `package.json`.
- **Oversized components** (e.g. `frontend/components/ItineraryView.tsx` ~941 lines) and weak error handling (`alert()` everywhere).

The fundamentals are solid (modern React, real AI integration, real auth) but the platform needs a cleanup pass before adding more features.

## 3. Findings by Category

### 3.1 Security 🔴

- **CRITICAL — Gemini API key exposed to the client.** `vite.config.ts` injects `process.env.API_KEY` into the bundle via `define`, and `frontend/services/geminiService.ts` reads it directly. Anyone can extract the key from the JS bundle or DevTools network tab.
- **No backend proxy.** `backend/api.ts` exists but is a stub and is not imported anywhere. There is no server-side surface to keep secrets or rate-limit requests.
- **Supabase RLS unverified.** The frontend uses the `anon` key (correct), but there is no in-repo confirmation that the `travels` table has Row-Level Security enabled. Without RLS, any user could read/write any row.
- **No input validation / sanitization** before sending user-supplied form fields, chat messages, and wishlist URLs to Gemini.
- **No rate limiting** on AI calls, so a malicious client (with the leaked key) can drain the Gemini quota.

### 3.2 Code Quality 🟠

- **Massive components.** `frontend/components/ItineraryView.tsx` is ~941 lines and mixes rendering, state, refinement orchestration, weather, and settings. `TravelForm.tsx` is ~371 lines.
- **Generic error handling.** Most failures surface as `alert("Failed to ...")`. No error boundaries, no inline error states, no retries.
- **Magic strings.** Gemini model names (`"gemini-2.5-flash"`, `"gemini-3-pro-preview"`), interest options, transport types, and activity types are sprinkled throughout components instead of being centralized.
- **TypeScript not strict.** `tsconfig.json` does not enable `"strict": true`, uses `allowJs` and `skipLibCheck`. Real type safety is partial.
- **Inconsistent state management.** Mix of `useState`, localStorage, and Supabase calls scattered across components — no global store or React Context for shared state.

### 3.3 Dependencies 🟠

- `@google/genai`: pinned to `"*"` — any breaking release will silently break production.
- No `eslint`, `prettier`, `vitest`, `husky`, `lint-staged`, or `@types/node`.
- `react-leaflet` + `leaflet` are imported but the map surface is minimal — possible bundle bloat for limited value.

### 3.4 Missing Infrastructure 🔴

- **No tests.** Zero `*.test.ts(x)` or `*.spec.ts(x)` files.
- **No linting / formatting.** No `.eslintrc*`, no `.prettierrc*`.
- **No CI.** No `.github/workflows/`.
- **No pre-commit hooks.** No husky, no `pre-commit-config.yaml`.
- **No `.env.example`.** New contributors have no idea which env vars are required (`API_KEY`, `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, etc.).
- **No error tracking.** No Sentry or equivalent.
- **README is one paragraph** ("Run and deploy your AI Studio app") and gives no architecture / contribution context.

### 3.5 Tech Debt / Dead Code 🟠

- Entire root-level `components/`, `services/`, `App.tsx`, `types.ts`, and `backend/api.ts` are unused.
- Unused root-level components: `ArtistCard.tsx`, `CustomCursor.tsx`, `FluidBackground.tsx`, `GlitchText.tsx`.
- Buttons referencing features that aren't wired up (e.g. "Download / Export" in `ItineraryView`).
- Wishlist analyzer falls back to hardcoded defaults silently on parse failure.

### 3.6 UX & Performance 🟡

- No skeleton loaders — only spinners.
- No accessibility pass: very few `aria-*` attributes, lots of `<div>` soup, no documented keyboard navigation.
- No bundle analysis; Leaflet is eagerly loaded even on routes that don't need a map.
- No offline / PWA / service worker.
- Dark mode toggle exists but persistence story unclear.

### 3.7 Strengths ✅

- Modern hooks-based React with immutable state updates.
- Real AI integration with structured prompt → typed `Itinerary` flow.
- Real auth + cloud persistence via Supabase.
- Thoughtful UX touches: animated landing, multi-step form, activity locking, refinement.
- Shared `shared/types.ts` keeps the data model consistent across services and components.

## 4. Product Vision — "The Only App a Traveler Needs"

The audit above is the *engineering* baseline. This section is the *product* baseline: where Cicerone should go so that a traveler can do **everything** — plan, book, review, navigate, modify, share, and remember a trip — without ever leaving the app, while still being able to "play" with the AI when they want to explore alternatives.

### 4.1 Product principles

1. **One screen, one trip.** Everything about a trip lives in a single workspace: timeline, map, budget, docs, chat, journal. No tab-hopping.
2. **AI is a collaborator, not a generator.** The first itinerary is just a draft. The real value is the loop: "show me cheaper", "make Tuesday a beach day", "what if we arrive late?", "swap this with something more local".
3. **Map-first.** Every plan is also a map. Every map is also a plan. The two views are bidirectional and always in sync.
4. **Online and offline parity.** A traveler in airplane mode in Lisbon should still see today's plan, navigate between activities, and check tickets.
5. **Export, don't trap.** A user must be able to push the itinerary into Google Maps, Apple Maps, their calendar, their wallet, or a PDF in one click. Lock-in kills travel apps.
6. **Two modes: "Organized" and "Playful".** Organized mode = checklist, reservations, reminders, peace of mind. Playful mode = AI sandbox, drag-and-drop on the map, "what if" scenarios. Both available, never forced.
7. **Personal, not generic.** The platform should learn from past trips, dietary needs, mobility, pace, budget appetite, and bring those to every new plan.

### 4.2 The traveler journey we want to own

| Phase            | What the user does                          | What Cicerone does                                                                                                                                                                       |
| ---------------- | ------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Dream**        | Browse, get inspired, save ideas            | Inspiration feed, public templates, save-from-Instagram/TikTok/web, mood boards, AI "surprise me"                                                                                        |
| **Plan**         | Pick destination, dates, vibe               | Multi-step form **and** chat-only mode, multi-city routing, trip templates, AI generates a draft itinerary with map, budget, weather, and reservations to make                           |
| **Refine**       | Tweak the draft until it feels right        | Conversational refinement, drag-and-drop on map and timeline, alternatives panel ("show 3 other options for Tuesday morning"), lock-in mandatory items, group voting                      |
| **Book**         | Lock in flights, hotels, tickets, tables    | Inline booking via partners (Skyscanner / Booking / GetYourGuide / OpenTable affiliate), or "I'll book myself" + paste confirmation → AI parses it into the plan                          |
| **Pack & prep**  | Get ready                                   | Smart packing list (weather + activities + airline limits), document checklist (visa, vaccines, insurance), currency + plug + SIM info, emergency contacts                                |
| **Travel**       | Live the trip                               | Day view with "what's next + leave by", live navigation handoff, real-time disruption handling ("flight delayed → reshuffle day 1"), spending tracker, photo/voice journal, offline mode |
| **Remember**     | Look back, share, plan the next             | Auto-generated trip recap with photos and route, public share link, "do it again" → clone trip as template, learnings feed back into the personalization model                          |

### 4.3 Modes

- **Organized Mode** — calm, checklist-driven, reservation-aware, notifications-on. Designed for "I just want it handled."
- **Playful Mode** — full canvas, drag-drop, alternative panels, AI brainstorming, "what if" simulator. Designed for "I love planning."
- A single toggle in the top bar switches between them; both modes operate on the same underlying trip data.

## 5. Feature Roadmap by Category

This is the menu. Section 6 turns it into checklist items grouped by priority.

### 5.1 Planning & itinerary intelligence

- **Multi-city / multi-leg trips** with automatic transit between cities (train, flight, drive) and re-pacing.
- **Time-aware scheduling** that respects opening hours, queue times, golden-hour for views, jet-lag on day 1, and meal windows.
- **Pace control** (chill / balanced / packed) with a slider that re-renders the day plan in real time.
- **Trip templates** ("3-day Lisbon foodie", "Iceland ring-road 7 days", "Tokyo with kids") — start from a template, then personalize.
- **Conversational refinement** — natural-language edits ("skip Monday morning", "add a cooking class", "swap dinner for something cheaper").
- **Alternatives panel** — for any activity, AI shows 3 swaps with reasons (cheaper / closer / better reviews / more local).
- **"What if" simulator** — preview the impact of a change ("what if we land 4h late?", "what if it rains all Wednesday?").
- **Constraint awareness** — dietary, accessibility, kids, religious, sober-friendly, LGBTQ+ safe, pet-friendly.
- **Personalization memory** — learns pace, budget level, cuisine preferences, and applies them to future trips (with explicit opt-in).

### 5.2 Map experience

- **Bidirectional map ↔ timeline.** Click an activity → highlight on map. Click a pin → highlight in timeline.
- **Per-day filter** with color-coded routes per day.
- **Route optimization** — TSP-ish "best order to visit these 6 places" with chosen transport mode (walk / transit / drive).
- **Travel-time annotations** between consecutive activities with mode toggle (walk / transit / drive / bike).
- **Drag-and-drop on the map** to reorder, with the timeline updating live.
- **Heatmap of the trip** — see where you'll spend most of your time across the city.
- **Offline map tiles** for the destination, downloaded when the trip is confirmed.
- **Custom pin styles** for booked vs. tentative vs. wishlist activities.
- **Distance / elevation summary** per day for walk-heavy plans.

### 5.3 Export & integrations (the "don't trap me" layer)

- **Google Maps export**:
  - One-click "Open day in Google Maps" with a directions URL chaining all stops.
  - "Save as Google Maps list" via the Google Maps API so all pins land in the user's account.
- **Apple Maps export**:
  - One-click `maps://` URL with multi-stop directions on iOS.
  - "Add to Apple Maps Guides" via shared link.
- **Calendar sync** — iCal feed + Google Calendar / Apple Calendar push (each activity becomes an event with location, notes, and link back to the app).
- **Apple Wallet / Google Wallet passes** for boarding passes, hotel check-ins, museum tickets parsed from confirmation emails.
- **PDF export** — printable itinerary, day-by-day, with QR codes linking back to the live plan.
- **Public share link** — read-only URL with map + timeline, optional password, optional expiry.
- **Notion / Obsidian / Markdown export** for the planner-nerd crowd.
- **Email forwarding inbox** — `trips@cicerone.app` style address; forward any booking confirmation and AI parses + attaches it to the right trip.
- **WhatsApp / Telegram bot** — chat with your trip from the messenger you already use ("what's tomorrow?", "find me a vegan dinner near hotel").

### 5.4 Booking & reservations

- **Inline flight + hotel + activity search** via partner APIs (Skyscanner, Booking.com, GetYourGuide, Viator, OpenTable affiliate links).
- **"I'll book it myself" mode** — user pastes a confirmation, AI extracts dates/times/PNR/locations, attaches to the trip.
- **Reservation tracking** — status (tentative / requested / confirmed / cancelled), confirmation numbers, cancellation deadlines, refund policies.
- **Price-drop alerts** for flights / hotels still in tentative state.
- **Visa, vaccine, and insurance checks** based on origin + destination + nationality.
- **Currency-aware budget** with live FX rates and per-category breakdown.

### 5.5 In-trip / live travel

- **Today view** — what's next, leave-by time, walking directions, weather, and a single "I'm ready" button.
- **Smart notifications** — "Leave in 15 min", "Reservation in 1h", "Rain expected at 3pm — swap park for museum?", "Flight delayed — your day 1 plan was updated".
- **Disruption handling** — flight cancelled, museum closed, strike happening: AI proposes a re-plan you can accept or tweak.
- **Live navigation handoff** to Google / Apple Maps in one tap.
- **Spending tracker** with receipt-photo OCR and per-day / per-category totals.
- **Translator + tipping calculator + plug adapter info** built in.
- **Emergency card** — local emergency numbers, nearest hospital, embassy / consulate, lost-passport flow.
- **Offline mode** — last-synced plan, map tiles, tickets, and emergency info available with no signal.
- **Photo & voice journal** — drop a photo into a day, AI captions it and attaches it to the right activity.

### 5.6 Discovery & inspiration

- **Inspiration feed** — destinations and templates curated by season, vibe, and your past trips.
- **Hidden gems** — AI surfaces local-favorite spots (not just TripAdvisor top-10).
- **Events during your dates** — concerts, festivals, exhibitions, sports automatically suggested.
- **Reviews aggregation** — pull from Google, TripAdvisor, Yelp, Reddit travel subs, and summarize.
- **"Save from anywhere"** — browser extension + iOS/Android share-sheet target. Dropping an Instagram reel, TikTok URL, or news article into Cicerone adds the place(s) to the trip wishlist.
- **Image-based input** — screenshot a place and AI identifies it and adds it.

### 5.7 Social & collaborative planning

- **Trip co-pilots** — invite travel partners, each can comment, vote, suggest, and lock activities.
- **Real-time multi-user editing** (Supabase Realtime) with presence cursors.
- **Group polls** — "lunch on Tuesday: pick one of these 3".
- **Public templates** — successful trips can be published as templates for others to clone.
- **Trip diary** — post-trip recap auto-generated, optional public profile.

### 5.8 AI architecture upgrades

- **Multi-agent design** — specialised sub-agents the orchestrator calls into:
  - **Planner** — generates and refines itineraries.
  - **Local Expert** — knows neighborhoods, hidden gems, local etiquette.
  - **Logistics** — flights, transit, distances, opening hours.
  - **Concierge** — bookings, reservations, confirmations.
  - **Budgeter** — money, currency, alternatives at lower cost.
  - **Disruption Handler** — replans on real-time issues.
- **Tool use** — first-class function-calling layer: Google Maps Places, weather, Skyscanner, Booking, GetYourGuide, OpenTable, currency, transit APIs.
- **Voice mode** — talk to Cicerone hands-free while walking.
- **Streaming responses** — token-by-token in chat and incremental rendering of itinerary cards.
- **Eval harness** — golden trips + automated scoring so prompt and model changes don't regress quality.
- **Model strategy** — default to a fast/cheap model (e.g. `gemini-2.5-flash`) for chat and refinement, escalate to a top-tier model for first-draft generation. Centralize in one config.

### 5.9 Account, profile, and trust

- **Travel profile** — preferences, restrictions, loyalty programs, passport info (encrypted, opt-in).
- **Trip library** — past, current, future trips with quick clone.
- **Privacy controls** — what the AI is allowed to remember; one-click export and delete.
- **Family / household accounts** — shared trips and shared payment methods.

4. What's the deployment target — Vercel only, or do we need Docker / self-host support?
5. Who owns secret rotation today, and where do production secrets live?
6. **Business model** — is Cicerone subscription, free + booking-affiliate revenue, or freemium? This drives whether we prioritize the booking layer or the planning UX first.
7. **Mobile strategy** — PWA-first, React Native wrapper, or native iOS/Android? Many of the live-trip features (notifications, offline maps, wallet passes, share sheets) are dramatically better on native.
8. **Partner APIs** — which booking partners do we have (or want) commercial agreements with? This decides what the "Book" button can do on day one.
9. **Map provider** — stay on free OpenStreetMap/Leaflet, or move to Google Maps / Mapbox for richer Places data? Affects export fidelity and cost.
10. **Memory & privacy posture** — how much do we want the AI to remember about a user, and where does that data live (Supabase, vector DB, on-device)?

## 8. Suggested Sequencing — from cleanup to product

A rough order to land things so the platform doesn't drown in half-built features:

1. **Cleanup pass (Section 6 critical + high)** — secret on backend, dead code gone, lint/tests/CI in place, ItineraryView split.
2. **Map & export polish** — bidirectional map↔timeline, day filters, Google Maps + Apple Maps export, iCal feed, public share link. This alone gives the "I don't need anything else" feeling for casual users.
3. **Live-trip basics** — Today view, smart notifications, offline map tiles, spending tracker. Turns Cicerone from a planner into a travel companion.
4. **Booking & docs** — paste-confirmation parser first (zero partner deals needed), then inline partner search, then wallet passes.
5. **AI architecture upgrade** — multi-agent split, tool layer, eval harness, streaming. This unblocks the "Playful" mode and makes refinement much better.
6. **Social & collab** — Realtime co-editing, group polls, public templates. Drives word-of-mouth growth.
7. **Inspiration & discovery** — feed, hidden-gems agent, save-from-anywhere extension. Pulls users in before they have a trip in mind.
8. **Mobile-first features** — PWA → native shell → push notifications, share sheet, voice mode.

Each numbered block could become its own future plan file (`plans/v1.md` for cleanup, `plans/v2.md` for map & export, etc.).
